из `../kit-generator/out/all`. Все пути в API и на клиенте шаблонные, ID — строки из transfermarkt.

## Пути к изображениям

- Страна: `/raster/country_flags/{country_id}.png`.
- Лига: `/raster/leagues/{league_id}.png`.
- Клуб: `/raster/teams_emblems/{club_id}.png`.
- Флаг клуба: `/raster/teams_flags/{club_id}.png`.
- Игрок: `/raster/players_faces_cutout/{player_id}.png`, если вырезки нет —
  `/raster/players_faces/{player_id}.jpg`. Выбор делает `server/canon.py` при отдаче игрока.
- Форма: `/raster/teams_kits/{club_id}/{main|white|black|reserve|gk1|gk2}.png`. Набор не у всех
  клубов полный; `GET /api/clubs/{id}/kits` возвращает только существующие файлы.

## `canon.db`

Таблицы: `meta`, `countries`, `leagues`, `clubs`, `players`, `national_teams`.

- У игрока — `overall`, `pot` и набор статов в JSON-поле `stats`. Число статов задаёт
  `ratings_output.json`; текущая сборка — 23 (добавлен `technical_penalty`), `meta.stats_per_player`
  хранит фактическое значение.
- Свободные агенты (`club_id IS NULL`) получают гражданство и стоимость из рейтингов.
- `meta` хранит `schema_version`, `source_snapshot_date`, количества и `ratings_source`.
- Схема собирается скриптом, ручных правок нет.

## Пересборка

```bash
python scripts/build_canon_db.py
```

Скрипт читает `data/json/` и ищет `ratings_output.json` в корне, затем в
`../ratings-generator/output.json`. Пути можно задать через `--json-dir`, `--ratings`, `--out`.

## Git

производные артефакты. JSON-исходники и код коммитятся.
