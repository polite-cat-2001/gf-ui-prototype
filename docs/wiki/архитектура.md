# Архитектура

Статус: **каркас**. Поднят FastAPI с read-only каноном, перенесены данные и статика, Svelte-клиент
собирает главное меню, выбор стороны, команды и формы; экран составов ещё заглушка.

## Что это

Песочница меню новой игры на Godot — футбольного симулятора. Функционально меню ориентируется на
`GameplayFootball-of_port` (ветка `of_port`), но визуальный язык у игры собственный. Цель — быстро
проверять UX экранов на веб-стеке, а затем переносить удачные решения в Godot. Прототип не
моделирует карьеру, матчи и трансферы: сервер — тонкий слой над каноном. Подробный объём меню —
[[функционал-меню]].

## Компоненты

| Часть | Технология | Ответственность |

| `web/` | Svelte 5 + Vite | Экраны, фокус, ввод, отрисовка данных канона |
| `web/src/App.svelte` | Svelte | Переключение экранов, статус API, нижняя легенда |
| `web/src/lib/KitSelect.svelte` | Svelte | Экран выбора формы: две плитки, карусели, готовность |
| `web/src/lib/KitArt.svelte` | Svelte + SVG | Футболка из цветов комплекта и паттернов |
| `web/src/lib/MatchPreview.svelte` | Svelte + SVG | Заглушка вида матча сверху с 22 фигурками в цветах форм |
| `web/src/lib/kits.js` | JS | Загрузка цветов формы и подписи комплектов |
| `server.py` | Python + FastAPI | Запуск приложения на `127.0.0.1:8766` |

| `scripts/build_canon_db.py` | Python | Сборка `canon.db` из `data/json/` и `ratings_output.json` |

## API

- `GET /api/health` — живость сервиса.
- `GET /api/meta` — версия схемы, дата снимка, количества.
- `GET /api/countries` — страны с флагом и числом лиг/клубов.
- `GET /api/leagues?country_id=` — лиги, фильтр по стране.
- `GET /api/clubs?league_id=|country_id=&limit=&offset=` — клубы.
- `GET /api/clubs/{id}` — клуб: лига, страна, цвета, стадион.
- `GET /api/clubs/{id}/players` — состав клуба без статов, отсортирован по роли и OVR.
- `GET /api/clubs/{id}/kits` — доступные PNG формы (`main`, `white`, `black`, `reserve`, `gk1`, `gk2`).
- `GET /api/teams/{id}/kit-specs` — цвета четырёх полевых комплектов (`main`, `white`, `black`,
  `reserve`): `shirt`, `shorts`, `pattern`, `pattern_color` уже разрешены в hex. Работает и для
  клубов (по ID канона), и для сборных (по имени из `national_specs.json`); недостающие сборные
  получают нейтральный fallback.
- `GET /api/clubs/{id}/ratings` — рейтинги клуба: `attack`, `midfield`, `defence`, `stars`.
- `GET /api/leagues/{id}/ratings` — те же рейтинги для всех клубов лиги.
- `GET /api/national-teams` — сборные, у которых есть страна в каноне: имя, флаг, эмблема и те же
  рейтинги.
- `GET /api/national-teams/{id}/players` — состав сборной без статов, отсортирован по роли и OVR.
- `GET /api/players/{id}` — игрок со статами из рейтингов.

Рейтинги клуба считаются на лету из состава (в базе их нет): линия — средний `overall`
лучших игроков роли, `attack` — 3 лучших из `CF/LM/RM`, `midfield` — 3 из `DM/CM/AM`,
`defence` — 4 из `CB/LB/RB`; пустая линия падает на средний `overall` лучших 11. Звёзды — от
среднего лучших 11 по линейной шкале `1 + (avg − 59) / 7`, шаг 0.5, диапазон 0.5–5.

Статика `/raster` раздаётся из `data/raster/` с `Cache-Control: no-cache`, а пути к флагам
отдаются с `?v=<mtime>`: заменённый ассет не залипает в кеше браузера. Если `web/dist` собран,
он монтируется в `/`.

## Потоки

1. **Запуск.** `python server.py` поднимает FastAPI на :8766 и раздаёт собранный Svelte.
2. **Разработка UI.** `cd web && npm run dev` — Vite на :5174 проксирует `/api` и `/raster` на :8766.
3. **Чтение данных.** Клиент ходит только в `/api/*`; изображения — по шаблонным путям `/raster/*`.
   Сервер ничего не кеширует и не меняет: `canon.db` открывается в режиме `mode=ro`.
4. **Сборка канона.** `python scripts/build_canon_db.py` читает `data/json/` и рейтинги, пишет
   `canon.db`. Скрипт ищет `ratings_output.json` в корне и в `../ratings-generator/output.json`.

## Инварианты

- **Канон только читается.** API не меняет `canon.db`; состояние UI живёт в клиенте.
- **Клиент не считает правила.** Числа, состав, сортировки и пути к фото приходят с сервера.
- **Данные не дублируются в коде.** Новые экраны берут клубы, игроков и формы из API.
- **Один источник истины по UI — Figma и [[ui-система]].**

## Границы

- Нет сейвов, карьеры, календаря, матчей и симуляции — это осталось в `../gf-career-prototype`.
- Формы клубов: цвета и паттерны берутся из `specs.json` и рисуются на клиенте в SVG; PNG из
  `kit-generator` остаются для Godot и как исходные ассеты. Редактор формы и 3D-модели не входят
  в проект.
- Центральное превью матча — намеренная заглушка: плоское поле с 22 фигурками, чтобы проверять
  реакцию формы на выбор. Настоящий вид с камеры будет в Godot.
- Перенос в Godot идёт вручную: веб-прототип фиксирует компоновку, состояния и поведение фокуса.
